# RS01 STM32H7 电机控制示例

使用 STM32H723 和 FDCAN2，通过 RobStride 私有协议控制 RS01 电机。工程保留完整的私有协议、MIT 驱动方法，当前应用使用私有协议速度模式。

## 当前版本状态

- 原电机 CAN ID `0x06`：已实机验证位置运动和速度运动。
- 已验证的单向速度参数：`0.2 rad/s`、限流 `0.5 A`、加速度 `1 rad/s²`。
- 另一台电机通过 ID 查询返回十进制 `127`，即 `0x7F`，但启动时出现位置查询或模式读回超时，原因尚未确认。
- 首次源码提交：`5d4946b`。该提交不包含相邻的 EIDE 配置目录。

**注意：当前程序上电或复位后会主动发送运动指令，随后循环正反转。**

## 硬件及 CAN 配置

| 项目 | 当前配置 |
| --- | --- |
| MCU | STM32H723，工程型号 STM32H723VGTx |
| CAN 外设 | FDCAN2 |
| 接收引脚 | PB5，连接 CAN 收发器 RXD |
| 发送引脚 | PB6，连接 CAN 收发器 TXD |
| 电机电源开关 | PC13，高电平开启 |
| 总线格式 | 经典 CAN，8 字节，关闭 BRS |
| 应用协议 | RobStride 私有协议，29 位扩展 ID |
| 波特率 | 1 Mbps |
| FDCAN 时钟 | PLL1Q，129 MHz |
| 位时序 | Prescaler = 1，Seg1 = 102，Seg2 = 26 |
| 自动重发 | 开启 |
| 主机 ID | `0xFD` |
| 当前目标电机 ID | `0x06` |

MCU 需要通过 CAN 收发器连接电机的 CANH/CANL。PC13 的作用取决于实际板卡，本工程按高电平开启电机电源处理。

接收过滤器允许标准数据帧和扩展数据帧进入 FIFO0，拒绝远程帧；应用再筛选目标电机的反馈。

## 当前 main.c 实际运行流程

1. 初始化系统、GPIO、FDCAN2；PC13 拉高。
2. 配置接收过滤器并启动 CAN，等待 1 秒。
3. 调用 `RS01_SpeedControl(0.2f, 0.5f)`。
4. 进入主循环：以 `+1 rad/s` 运行 5 秒，再以 `-1 rad/s` 运行 5 秒，反复执行。

启动段的 `0.2 rad/s` 后没有专门等待，因此进入主循环后会很快重新配置为 `+1 rad/s`。正负方向由电机安装及厂家方向定义决定。

当前主循环使用两段 `HAL_Delay(5000U)`，期间没有轮询反馈，可能造成接收 FIFO 积压。主循环中的速度调用也没有将返回值重新保存到 `rs01_speed_status`；该变量目前只保存启动段调用结果。后续排查应区分实际代码行为与之前验证过的单向测试。

`RS01_SpeedControl()` 内部流程：

```text
读取当前位置，确认可通信
  → 失能
  → 写入速度模式 0x7005 = 2
  → 重试查询模式并确认读回为 2
  → 使能，等待新的运行状态反馈
  → 设置电流上限和加速度
  → 先写零速度，再写目标速度
```

虽然速度控制本身不需要当前位置，当前版本仍保留位置查询作为启动准备条件；这也是新电机出现超时的一个已知阻塞点。

任一步失败，调用方进入 `Error_Handler()`，关闭中断并停在死循环。等待不会自动恢复，需要复位后重新运行。

## 修改 ID 和运动参数

目标地址在 `RS/Robstride01.cpp` 中：

```cpp
static const uint8_t MOTOR_ID = 0x06U;
```

该常量同时用于 C 接口发送和反馈筛选，修改它不会改写电机自身保存的 ID。修改后需重新编译、烧录。

速度控制示例：

```c
rs01_speed_status = RS01_SpeedControl(0.2f, 0.5f);
```

第一个参数为目标速度，单位 `rad/s`；第二个参数为电流上限，单位 `A`，不是速度上限。加速度在驱动中通过参数 `0x7022` 设置，当前为 `1 rad/s²`。

换算：`角度 = 弧度 × 180 / π`，`rpm = rad/s × 60 / (2π)`。因此 `0.2 rad/s ≈ 1.91 rpm`，`1 rad/s ≈ 9.55 rpm`。

## main.c 可直接调用的接口

| 接口 | 功能 |
| --- | --- |
| `RS01_FindMotorId(&id)` | 扫描私有协议设备，返回第一个回复的 ID；不改配置、不使能 |
| `RS01_ReadPosition(&position)` | 读取位置，单位 rad，最多等待 3 秒 |
| `RS01_SetCspMode()` | 选择 CSP 位置模式 |
| `RS01_SetSpeedLimit(speed)` | CSP 速度上限；当前示例接口限制为 `(0, 0.15] rad/s` |
| `RS01_Enable()` | 发送使能指令 |
| `RS01_SetPosition(position)` | 设置绝对目标位置，单位 rad |
| `RS01_SpeedControl(speed, current)` | 完整速度模式启动流程 |
| `RS01_PollFeedback()` | 接收并解析反馈，运行阶段轮询参数 |

完整 C++ 类 `RobStride_Motor` 的方法按协议在头文件中分区。类成员不能在 `main.c` 中作为普通函数直接调用；原有大部分成员方法返回 `void`，不能与 `HAL_OK` 比较。

当前应用只使用私有协议。MIT 方法已恢复，但未通过本次实机验证；CANopen 控制栈未实现。切换电机协议后，还需匹配 MCU 的报文发送和反馈解析，不能只改本地协议标志。

## ID 查询与协议说明

手册 `RS01使用说明书260428(1).pdf` 的印刷第 37 页明确列出：`0` 为私有协议（默认），`1` 为 CANopen，`2` 为 MIT；协议切换重新上电生效。

私有协议 ID 查询使用通信类型 `0`。有效回复的低 8 位为 `0xFE`，电机 ID 为：

```c
motor_id = (response_id >> 8) & 0xFF;
```

`RS01_FindMotorId()` 按 `0x00～0xFF` 逐个查询，每个地址等待约 25 ms；单次查询只返回第一个设备。它适用于当前的私有协议、1 Mbps 配置，当前 `main.c` 没有调用扫描。

扫描失败还可能与供电、波特率、协议或连接有关，不能只判断为 ID 错误。`HAL_OK` 的有效 ID 回复说明设备响应了私有协议查询，但不保证后续参数控制流程全部兼容。

## 调试与待排查事项

在调试器暂停后重点查看：

| 变量 | 用途 |
| --- | --- |
| `rs01_speed_status` | 启动段速度控制返回值 |
| `rs01_speed_stage` | 当前控制阶段，见下表 |
| `rs01_motor.drw.run_mode.data` | 模式读回，速度模式应为 2 |
| `rs01_motor.drw.spd_ref.data` | 目标速度读回 |
| `rs01_motor.drw.limit_cur.data` | 电流上限读回 |
| `rs01_motor.drw.mechVel.data` | 参数查询得到的实际速度 |
| `rs01_motor.Pos_Info.pattern` | 最近状态帧：0 复位、1 标定、2 运行 |
| `rs01_motor.error_code` | 最近状态帧中的故障位 |
| `rs01_mode_rx_count` / `rs01_mode_rx_data` | 模式回复次数及原始数据 |
| `rs01_startup_tx` / `rs01_startup_rx` | 启动收发记录；容量有限，不是持续总线抓包 |

阶段含义：`0` 查询位置，`1` 失能，`2` 写模式，`3` 等待模式确认，`4` 等待使能确认，`5` 写控制参数，`6` 已下发目标速度。阶段 6 不代表轴已达到目标速度，需要核对实际反馈。

新电机后续排查顺序：

1. 单独连接待测电机，确认供电及 ID；控制代码使用相同目标 ID。
2. 核对固件版本及上位机中的协议配置。手册默认私有协议，但保存过的配置可能不同。
3. 捕获实际参数回包，区分没有回复、读取失败和解析条件不匹配。
4. 若运行阶段已确认，再核对目标速度、限流和实际速度，不直接将不转归因于硬件损坏。

原电机曾在限流 `0.15 A` 时只振动；将限流提高到 `0.5 A`、加速度降到 `1 rad/s²` 后能转。两项同时修改，尚未单独验证各自影响。
