# RS01 双电机位置控制

调用流程只有三部分：

1. 主程序进入 while 前：RS01_Init() 初始化软件参数，再分别调用 RS01_SpeedInit()，阻塞完成两个电机配置。
2. CAN 接收中断：update_motorstate() 解析反馈并累计多圈位置。
3. TIM6 每10ms中断：分别调用两个电机的 RS01_PositionTask()，执行位置PID并非阻塞发布速度。

主循环只在有新命令时调用 RS01_StartMove()；不要再调用 RS01_Task() 或旧的 SpeedInitTask。
初始化可以阻塞，发布速度和位置控制中断中没有 HAL_Delay 或等待回复。
初始化时控制定时器必须停止，CAN接收中断和SysTick必须开启。

```c
RS01_Init();
if (RS01_SpeedInit(&Motor_left, 2000U) != HAL_OK) Error_Handler();
if (RS01_SpeedInit(&Motor_right, 2000U) != HAL_OK) Error_Handler();
// 启动10ms控制定时器后，主程序收到一条新指令时：
RS01_StartMove(&Motor_left, 2.0f, 3.0f);
RS01_StartMove(&Motor_right, 2.0f, 3.0f);
```

main.c 保留上电测试：两台电机正转2圈，等两边完成后反转2圈，最终step=6，不自动重复。不需要自动运动时删除对应StartMove调用。
state 为 IDLE 时初始化完成，MOVING 时运动中，STOPPING 时等待停止，DONE 时运动完成，FAULT 时故障锁存。
初始化步骤和超时使用局部变量，模式回复使用独立的初始化确认变量，不占用Motor_t。失能状态可能不返回类型2，因此先确认模式，再使能并等待运行反馈。模式查询每100ms重试，整个初始化仍受统一超时限制。
主程序更新目标及清积分在同一短临界区完成，避免定时器读到半条命令。
HAL发送也用短临界区保护，不循环等待发送队列。

默认左ID=5、方向=+1，右ID=7、方向=-1；电流限制1A，加速度5rad/s²。
库默认Kp=1、Ki=Kd=0；本版main.c将两台电机Kp设置为1.5，运动速度上限2.5rad/s。参数在初始化/运动前配置，不要在运动中直接修改。
本次实测保留的位置阈值和速度阈值均为0.15，单位分别为rad和rad/s。位置0.15rad约8.59°，不是角度制的0.15°。连续满足10次进入STOPPING，再发送零速度并等10个低速周期，最后置DONE。
IDLE和DONE也每10ms发布零速度，并检查反馈。完成后保持使能和零速度目标，不是位置闭环保持。新任务可从IDLE或DONE启动。
默认30秒运动超时（包含STOPPING）、100ms反馈超时；配置宏在RS01.h顶部。

TIM6 当前按 main.c 中 APB1 不分频配置计算，时钟=PCLK1，100Hz。
如后续修改 APB 分频或 TIMPRE，需要同步确认定时器时钟。
CAN接收优先级5，控制定时器优先级6；CAN中断不发送命令。
故障后定时器持续尝试发失能帧；总线断开时无法用CAN保证物理停车。
重新初始化前先停定时器并确认机构已停止；重新初始化会清累计位置。
两个轴独立，任一轴故障不会自动停止另一个轴；联动需求需上层实现。
不要与旧库的阻塞读参数、PP运动函数混用；旧接收队列不再由这个回调填充。

## 调试记录

在调试器中展开全局变量rs01_debug即可查看诊断，无需在控制中断内打印。计数及最近一次发送状态持续更新；captured为1后，首次超时的time_ms、feedback_age、previous_state和CAN寄存器现场不再覆盖。只有超时分支记录现场，不代表所有HAL_ERROR都会更新它。

- init_motor_id、init_step、init_run_mode：初始化停在哪里。步骤0～6发送配置、7等待模式回复、8使能、9等待运行反馈、10成功。
- right_count只统计右电机类型2反馈；right_any_count统计通过格式检查且匹配右电机ID的扩展帧，包含主机地址过滤前的帧。两者含义不同。
- left/right_start_status是最近一次启动返回值，HAL_OK表示任务接受，不表示运动完成。
- left/right_speed_cmd记录最近一次尝试发布的速度；left/right_tx_status为HAL入队结果，不保证总线实际发送或电机执行。
- control_count统计两台电机的位置任务调用总数，正常每秒约增加200次。
- previous_state区分运动超时、停止确认超时和DONE之后反馈中断；feedback_age使用实际触发判断的时间差，单位ms。
- 调试断点会暂停MCU而电机仍可能上报，应尽量连续运行到首次故障后再检查记录。

## 本版验证

用户在接好并整理CAN线后，连续10遍正反转测试均通过。此前曾出现CAN线脱落及整理线缆后恢复的现象，因此本版保留反馈超时保护；接触不良或干扰的具体原因尚未定论。
软件另有初始化无失能反馈、模式查询丢失重试、非阻塞发送、镜像方向、跨圈累计、到位完成及超时现场锁存的模拟检查。该检查不替代实际负载和布线验证。
