# 激光抓篮联调

激光随夹爪运动；两侧电机统一正方向前进时，距离减小。使用现有
`Motor_t.direction`，不额外翻转右侧方向。

## 运行

1. 上电后初始化 CAN、两侧速度模式和 TIM6，等待手动触发，不自动伸出。
2. 监视 `basket.init_status`，应为 `HAL_OK`（0）；监视 `basket.distance_mm`
   和 `basket.confidence`，确认测量的是篮子。
3. 准备好后把 `basket_request` 设为 1 并继续运行。
4. 流程：张开夹爪 → 前进并接近30 mm → 零速、两侧停稳且3次新测距在容差内
   → 抓取 → 等待700 ms → 返回两侧记录的出发位置 → 两侧到位 → 释放。
5. `basket.state == BASKET_DONE` 表示本次完成，不自动重复。
6. `basket_request = 2` 中止；故障后不自动返回或松开夹爪，重启并检查机构。

## 首轮参数

集中配置在 `basket.h`：目标30 mm、容差±3 mm、置信度至少50、有效测距
超时300 ms、前进最大2圈、前进和返回最高1.5 rad/s，距离越近速度上限越低。
这些是首轮联调参数，不代表已知的直线距离/圈数比例。
速度、最大圈数、容差和激光置信度应按实际机构与传感器数据调整。

最大行程或30秒阶段时限先到则故障，不能把未到篮子的位置当作抓取点。
未知机构传动比和制动距离，因此30 mm只是停止目标，不能保证不会越过；
若停后测距超出27～33 mm，不继续抓取。先低速、短行程实测。
左右轴采用独立位置环、同速上限，没有机械同步误差反馈控制。
返回到启动时记录的电机角度，不是寻机械原点；零速度模式也不是静态位置保持。

`Servo_catch`/`Servo_release` 现返回发送状态；700 ms等待不是夹紧成功检测。
使用原来的抓取角90°和释放角10°、运动时间500 ms，未修改舵机模式或校准。
UART4回复持续取走，避免回复缓存满后停收；当前流程未解析舵机动作确认。

## 状态与错误

`basket.state`：IDLE=0、OPENING=1、APPROACH=2、STOPPING=3、GRIPPING=4、
RETURNING=5、RELEASING=6、DONE=7、FAULT=8。

`basket.error`：NONE=0、INIT=1、MOTOR=2、LASER=3、TOO_CLOSE=4、TRAVEL=5、
TIMEOUT=6、SERVO=7、ABORT=8。停止后测距超出容差也使用TOO_CLOSE。
初始化/测距/电机故障时，10 ms定时控制持续尝试将两侧电机失能；
CAN断线时不能仅凭软件保证物理停止。

不要在机构运动时使用断点暂停MCU；连续运行后再查看状态。
